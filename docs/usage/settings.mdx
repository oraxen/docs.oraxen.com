# ⚙️ Settings

## Overview

Oraxen is managed through the <code>/oraxen</code> root command. It also includes the <code>/o</code> and <code>/oxn</code> aliases. Most subcommands are for administrators. Players can use commands to browse items and glyphs or toggle HUDs.

Settings are stored in <code>plugins/Oraxen/settings.yml</code>.

## Settings

The snippets use current setting names. Check the generated `settings.yml` for exact default values.

```yaml
debug: false
```

<Details>
<summary id="general"><strong>🧩 <code>general</code></strong></summary>

Controls language, update checks, automatic settings updates, the first-run message, and MiniMessage formatting.

```yaml
general:
  language: english
  update-checker:
    enabled: true
    interval: 24h
  auto-update:
    settings: true
    paper-config: true
  introduction:
    enabled: true
    console-sent: false
  formatting:
    inventory-titles: true
    titles: true
    subtitles: true
    action-bar: true
    anvil: true
    signs: true
    chat: true
    books: true
```

<code>general.language</code> selects the message language.<br />
<code>general.update-checker.enabled</code> checks for Oraxen updates and notifies players with <code>oraxen.update.notify</code> when they join.<br />
<code>general.update-checker.interval</code> sets the time between checks. Use a number followed by <code>s</code>, <code>m</code>, <code>h</code>, or <code>d</code>. The minimum is <code>10m</code>.<br />
<code>general.auto-update.settings</code> updates `settings.yml` with current options when Oraxen starts.<br />
<code>general.auto-update.paper-config</code> updates <code>paper-global.yml</code> to disable block updates for custom blocks.<br />
<code>general.introduction.enabled</code> controls the first-run welcome message.<br />
<code>general.introduction.console-sent</code> records whether Oraxen has shown the welcome message in the console.<br />
<code>general.formatting</code> controls MiniMessage formatting for inventory titles, titles, subtitles, action bars, anvils, signs, chat, and books. Legacy color codes such as <code>&amp;c</code> are not supported.
</Details>

<Details>
<summary id="configuration"><strong>🛠️ <code>configuration</code></strong></summary>

Controls default file generation, automatic item model-data assignment, and the fallback item used for invalid item configs.

```yaml
configuration:
  defaults:
    assets: true
    configs: true
  items:
    model-data:
      skipped-numbers: []
      disable-automatic: false
    fallback:
      material: PODZOL
      exclude-from-inventory: false
      inject-id: false
```

<code>configuration.defaults.assets</code> generates Oraxen default resource-pack assets.<br />
<code>configuration.defaults.configs</code> generates Oraxen default item and glyph configs.<br />
<code>configuration.items.model-data.skipped-numbers</code> reserves CustomModelData values for other uses. Entries can be numbers or ranges such as <code>1-4</code>.<br />
<code>configuration.items.model-data.disable-automatic</code> disables automatic CustomModelData assignment.<br />
<code>configuration.items.fallback.material</code> sets the material used when an item config cannot be loaded.<br />
<code>configuration.items.fallback.exclude-from-inventory</code> hides the fallback item from the inventory menu.<br />
<code>configuration.items.fallback.inject-id</code> adds the Oraxen item ID tag to the fallback item.
</Details>

<Details>
<summary id="glyphs"><strong>✦ <code>glyphs</code></strong></summary>

```yaml
glyphs:
  emoji-list-permission-only: true
  unicode-completions: true
  disable-automatic-code: false
```

<code>glyphs.emoji-list-permission-only</code> shows players only glyphs they have permission to use.<br />
<code>glyphs.unicode-completions</code> shows Unicode values instead of glyph placeholders in tab completion.<br />
<code>glyphs.disable-automatic-code</code> disables automatic glyph-code assignment.
</Details>

<Details>
<summary id="custom-armor"><strong>🛡️ <code>custom-armor</code></strong></summary>

Controls the custom armor system and its component or trim settings.

```yaml
custom-armor:
  type: COMPONENT
  auto-select-type: true
  disable-leather-repair: true
  component:
    auto-assign-component: true
  trims:
    material-replacement: CHAINMAIL
    auto-assign-settings: true
```

<code>custom-armor.type</code> selects <code>COMPONENT</code>, <code>TRIMS</code>, or <code>NONE</code>.<br />
<code>custom-armor.auto-select-type</code> chooses a supported armor type for the server version.<br />
<code>custom-armor.disable-leather-repair</code> requires a copy of the custom armor piece instead of leather for repairs.<br />
<code>custom-armor.component.auto-assign-component</code> assigns the equippable-model component unless the item config specifies one.<br />
<code>custom-armor.trims.material-replacement</code> selects the vanilla armor material used for trim-based armor. Valid values are <code>CHAINMAIL</code>, <code>IRON</code>, <code>GOLD</code>, <code>DIAMOND</code>, <code>NETHERITE</code>, and <code>LEATHER</code>.<br />
<code>custom-armor.trims.auto-assign-settings</code> assigns the trim and item flag unless the item config specifies them.
</Details>

<Details>
<summary id="updater"><strong>🔁 <code>updater</code></strong></summary>

Controls when Oraxen updates items and placed furniture to match their item configs.

```yaml
updater:
  items:
    update-items: true
    update-tile-entity-contents: true
    update-entity-contents: true
    override-renamed-items: false
    override-item-lore: false
    update-on-reload: true
  furniture:
    update-furniture: true
    update-on-reload: false
    update-on-load: false
    experimental-type-update: false
    experimental-fix-broken: false
```

<code>updater.items.update-items</code> updates player inventory items when players join.<br />
<code>updater.items.update-tile-entity-contents</code> updates items in loaded block inventories such as chests and furnaces.<br />
<code>updater.items.update-entity-contents</code> updates items held by loaded entities such as item frames and mobs.<br />
<code>updater.items.override-renamed-items</code> also updates items renamed by players.<br />
<code>updater.items.override-item-lore</code> replaces item lore with the configured lore.<br />
<code>updater.items.update-on-reload</code> updates online players after <code>/oraxen reload items</code> or <code>/oraxen reload all</code>.<br />
<code>updater.furniture.update-furniture</code> keeps placed furniture synced with its item config.<br />
<code>updater.furniture.update-on-reload</code> updates furniture after item or full reloads.<br />
<code>updater.furniture.update-on-load</code> updates furniture when its entity loads.<br />
<code>updater.furniture.experimental-type-update</code> enables furniture type updates.<br />
<code>updater.furniture.experimental-fix-broken</code> attempts to repair furniture that is not placed or loaded correctly.
</Details>

<Details>
<summary id="pack"><strong>📦 <code>pack</code></strong></summary>

Controls resource-pack generation, imports, hosting, delivery, and pack-status actions.

### Generation

```yaml
pack:
  generation:
    generate: true
    unprotected-location: ""
    mcmeta: true
    multi-version-packs: false
    model-definitions: true
    model-data:
      float: false
      ids: false
    predicates: false
    fix-force-unicode-glyphs: true
    auto-generated-models-follow-texture-path: false
    atlas:
      generate: true
      type: SPRITE
      exclude-malformed-from-atlas: true
  verification: true
  excluded-file-extensions: []
  compression: BEST_COMPRESSION
  protection:
    size-spoofing: false
    obfuscation:
      type: NONE
  comment: "The content of this texture pack belongs to the owner of the Oraxen plugin."
```

<code>pack.generation.generate</code> enables resource-pack generation.<br />
<code>pack.generation.unprotected-location</code> optionally writes an unprotected, unobfuscated ZIP after pack generation and before obfuscation. Oraxen does not upload or send this export to players. Relative paths use the server working folder, and Oraxen creates parent folders as needed. Keep the output outside <code>plugins/Oraxen/pack</code> so Oraxen does not import it on a later build.<br />
<code>pack.generation.mcmeta</code> generates <code>pack.mcmeta</code> and overlay entries. Disable it to use the file in <code>plugins/Oraxen/pack</code> as supplied and manage overlays yourself.<br />
<code>pack.generation.multi-version-packs</code> creates separate packs for clients on Minecraft 1.20 through 1.21.3 and clients on 1.21.4 and above. ViaVersion detects each client version. Without ViaVersion, players receive the server-version pack. Use an upload type other than self-host.<br />
<code>pack.generation.model-definitions</code> generates modern item definitions for Minecraft 1.21.4 and above. Oraxen uses legacy item model overrides for clients that do not support item definitions.<br />
<code>pack.generation.model-data.float</code> selects models with <code>custom_model_data.floats[0]</code> and also sets integer CustomModelData. Items must define <code>pack.custom_model_data</code>.<br />
<code>pack.generation.model-data.ids</code> selects models with a string such as <code>oraxen:item_id</code> in <code>custom_model_data.strings[0]</code>. Items must define <code>pack.custom_model_data</code>.<br />
Enable at most one of <code>model-data.float</code> and <code>model-data.ids</code>. Both write to the same vanilla item-definition files.<br />
<code>pack.generation.predicates</code> generates legacy item model overrides on Minecraft 1.21.4 and above for tools that read those files.<br />
<code>pack.generation.fix-force-unicode-glyphs</code> fixes glyphs that do not display when Force Unicode is enabled.<br />
<code>pack.generation.auto-generated-models-follow-texture-path</code> places generated models under the source texture path.<br />
<code>pack.generation.atlas.generate</code> generates texture atlas files. <code>pack.generation.atlas.type</code> selects <code>SPRITE</code> or <code>folder</code> mode. <code>pack.generation.atlas.exclude-malformed-from-atlas</code> omits malformed textures from the atlas.<br />
<code>pack.verification</code> checks textures and models for valid resource-pack formatting.<br />
<code>pack.excluded-file-extensions</code> lists file extensions omitted from the final ZIP.<br />
<code>pack.compression</code> sets the ZIP compression level.<br />
<code>pack.protection.size-spoofing</code> spoofs ZIP entry sizes to discourage extraction.<br />
<code>pack.protection.obfuscation.type</code> selects <code>NONE</code>, <code>SIMPLE</code>, or <code>FULL</code>. <code>SIMPLE</code> renames resource paths. <code>FULL</code> also renames namespaces.<br />
<code>pack.comment</code> sets the ZIP archive comment.

### Import

```yaml
pack:
  import:
    modelengine: true
    merge:
      fonts: true
      duplicates: true
      item-base-models: false
    exclude:
      core-shaders: false
    retain-custom-model-data: true
```

<code>pack.import.modelengine</code> imports the latest available ModelEngine resource pack during Oraxen pack generation when ModelEngine is enabled. Oraxen waits for ModelEngine to finish generating its pack.<br />
<code>pack.import.merge.fonts</code> merges duplicate font files and excludes the original duplicates from the final pack.<br />
<code>pack.import.merge.duplicates</code> merges duplicate imported resources when possible.<br />
<code>pack.import.merge.item-base-models</code> attempts to merge item base-model JSON files such as <code>paper.json</code> instead of generating item configs from them.<br />
<code>pack.import.exclude.core-shaders</code> removes imported Minecraft core shaders from the pack.<br />
<code>pack.import.retain-custom-model-data</code> keeps CustomModelData values from imported files. This can conflict with Oraxen items that use the same values.

### Upload

```yaml
pack:
  upload:
    enabled: true
    type: polymath
    polymath:
      server: atlas.oraxen.com
      secret: oraxen
    lobfile:
      api-key: ""
      pack-name: Oraxen
    s3:
      endpoint: https://s3.us-east-1.amazonaws.com
      access-key: ""
      secret-key: ""
      bucket: ""
      region: us-east-1
      prefix: oraxen
      path-style: true
      public-url: ""
      presigned-url-expiry: 86400
    self-host:
      host: 0.0.0.0
      port: 8080
      domain: localhost:8080
```

<code>pack.upload.enabled</code> enables pack uploads.<br />
<code>pack.upload.type</code> selects <code>lobfile</code>, <code>polymath</code>, <code>s3</code>, <code>self-host</code>, or <code>external</code>.<br />
The <code>polymath</code>, <code>lobfile</code>, <code>s3</code>, and <code>self-host</code> subsections contain provider-specific settings. <code>pack.upload.options.class</code> names the provider class when <code>type</code> is <code>external</code>.<br />
<code>pack.upload.lobfile.pack-name</code> sets the Lobfile pack name. Multi-version uploads add the client version to this name.<br />
<code>pack.upload.s3.prefix</code> sets an optional folder within the bucket. Leave it empty to store packs at the bucket root.<br />
<code>pack.upload.s3.public-url</code> sets an optional public or CDN URL for the bucket. <code>pack.upload.s3.presigned-url-expiry</code> sets the URL lifetime in seconds when no public URL is set.<br />
<code>pack.upload.self-host.host</code> is the bind address. <code>0.0.0.0</code> listens on all interfaces. <code>pack.upload.self-host.port</code> is the HTTP port, and <code>domain</code> is the address players use to download the pack.

### Dispatch

```yaml
pack:
  dispatch:
    send: true
    mode: JOIN
    timeout: 30s
    exclude: []
    delay: -1
    mandatory: true
    disable:
      movement: true
      damage: true
    prompt: "Accept the pack to enjoy the Oraxen experience"
    layer: ""
```

<code>pack.dispatch.send</code> sends the pack to players.<br />
<code>pack.dispatch.mode</code> selects <code>JOIN</code> or <code>PRE-JOIN</code>. <code>PRE-JOIN</code> requires Paper 1.21.7 or above and falls back to <code>JOIN</code> if the server does not support it.<br />
<code>pack.dispatch.timeout</code> sets how long Oraxen waits for a <code>PRE-JOIN</code> response before login continues. It accepts values such as <code>30s</code>, <code>500ms</code>, <code>1m</code>, or <code>20t</code>.<br />
<code>pack.dispatch.exclude</code> lists client versions that should not receive the pack. Quote each rule, such as <code>'&lt; 1.12'</code> or <code>'= 1.21.11'</code>.<br />
<code>pack.dispatch.delay</code> sets a delay in seconds for <code>JOIN</code> mode. Values at or below zero send the pack immediately.<br />
<code>pack.dispatch.mandatory</code> makes the pack required.<br />
<code>pack.dispatch.disable.movement</code> freezes player movement while the pack loads. <code>pack.dispatch.disable.damage</code> prevents damage during that time.<br />
<code>pack.dispatch.prompt</code> sets the prompt shown with the pack request.<br />
<code>pack.dispatch.layer</code> sets the pack layer. Use a nonempty value to keep resource packs sent by your proxy from being cleared.

### Receive

```yaml
pack:
  receive:
    enabled: true
    loaded:
      actions:
        sound:
          enabled: true
          type: oraxen:welcome
          volume: 1.0
          pitch: 1.0
        delay: 5
        message:
          enabled: false
          type: ACTION_BAR
          content: ResourcePack loaded
        commands:
          console: []
          player: []
          opped-player: []
    accepted:
      actions:
        message:
          enabled: false
          type: ACTION_BAR
          content: ResourcePack accepted
        commands:
          console: []
          player: []
          opped-player: []
    denied:
      actions:
        message:
          enabled: false
          type: CHAT
          content: You refused the ResourcePack
        commands:
          console: []
          player: []
          opped-player: []
    failed-download:
      actions:
        commands:
          console: []
          player: []
          opped-player: []
    failed-reload:
      actions:
        commands:
          console: []
          player: []
          opped-player: []
    downloaded:
      actions:
        commands:
          console: []
          player: []
          opped-player: []
    invalid-url:
      actions:
        commands:
          console: []
          player: []
          opped-player: []
    discarded:
      actions:
        commands:
          console: []
          player: []
          opped-player: []
```

<code>pack.receive.enabled</code> enables pack status actions.<br />
<code>pack.receive.loaded.actions.sound</code> controls the sound played after the pack loads. Its <code>enabled</code>, <code>type</code>, <code>volume</code>, and <code>pitch</code> options set whether the sound plays and how it sounds.<br />
<code>pack.receive.loaded.actions.delay</code> delays loaded actions by a number of ticks.<br />
<code>pack.receive.&lt;status&gt;.actions.message</code> controls the message for a pack status. Valid message types are <code>KICK</code>, <code>CHAT</code>, <code>ACTION_BAR</code>, and <code>TITLE</code>. Click and hover elements require <code>CHAT</code>.<br />
<code>pack.receive.&lt;status&gt;.actions.commands</code> runs commands as the console, player, or temporarily opped player.<br />
Supported statuses are <code>loaded</code>, <code>accepted</code>, <code>denied</code>, <code>failed-download</code>, <code>failed-reload</code>, <code>downloaded</code>, <code>invalid-url</code>, and <code>discarded</code>. On Minecraft 1.20.3 and above, <code>failed-reload</code>, <code>downloaded</code>, <code>invalid-url</code>, and <code>discarded</code> are also available.
</Details>

<summary id="utils"><strong>⚙️ <code>utils</code></strong></summary>

Controls recipe behavior, scoreboard and tablist display, armor-equip exclusions, and vanilla display transforms.

```yaml
utils:
  hide:
    scoreboard:
      numbers: false
      background: false
    tablist:
      background: false
  recipes:
    reset: true
    add-to-book: true
  armor-equip-event-bypass:
    - FURNACE
    - CHEST
```

<code>utils.hide.scoreboard.numbers</code> hides scoreboard numbers.<br />
<code>utils.hide.scoreboard.background</code> hides the scoreboard background on supported Minecraft versions.<br />
<code>utils.hide.tablist.background</code> hides the tablist background on supported Minecraft versions.<br />
<code>utils.recipes.reset</code> resets Oraxen recipes when the plugin reloads.<br />
<code>utils.recipes.add-to-book</code> adds permitted recipes to player recipe books.<br />
<code>utils.armor-equip-event-bypass</code> lists blocks that do not trigger armor equipping when right-clicked.<br />
<code>utils.display.shield</code>, <code>utils.display.bow</code>, and <code>utils.display.crossbow</code> set vanilla display transforms used by custom shields, bows, and crossbows.
</Details>

<summary id="inventory"><strong>🗂️ <code>inventory</code></strong></summary>

Configures the item browser GUI opened with Oraxen commands.

```yaml
inventory:
  title: "<shift:-18><glyph:menu_items><shift:-193>"
  rows: 6
  slots: 45
  previous-page-icon: arrow_previous_icon
  next-page-icon: arrow_next_icon
  exit-icon: exit_icon
  layout:
    armors:
      slot: 1
      icon: emerald_chestplate
      name: "<green>Armors"
      title: "<main_menu_title>"
```

<code>inventory.title</code> sets the main browser title.<br />
<code>inventory.rows</code> sets the number of GUI rows. <code>inventory.slots</code> sets the number of item slots per page.<br />
<code>inventory.previous-page-icon</code>, <code>inventory.next-page-icon</code>, and <code>inventory.exit-icon</code> set the navigation icons. Each accepts an Oraxen item ID or a vanilla material.<br />
<code>inventory.layout</code> defines category buttons. Each category can set <code>slot</code>, <code>icon</code>, <code>name</code>, and <code>title</code>.
</Details>

<summary id="studio"><strong>🔗 <code>studio</code></strong></summary>

```yaml
studio:
  url: https://studio.oraxen.com
  secret: ""
  auto-sync: true
```

<code>studio.url</code> sets the Oraxen Studio address used by <code>/oraxen studio connect</code>, <code>pull</code>, and <code>push</code>.<br />
<code>studio.secret</code> stores the scoped token created by <code>/oraxen studio connect</code>. Keep it private.<br />
<code>studio.auto-sync</code> reloads items and the pack when Studio sends a sync event.
</Details>
