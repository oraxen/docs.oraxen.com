# 🕹️ Usage

## Overview
BedrockGen converts Oraxen's resource pack into the Bedrock files needed by Geyser. Configure Oraxen to export a separate unprotected, unobfuscated ZIP for BedrockGen. Oraxen can keep its normal pack protection and obfuscation enabled for players. After the first install, BedrockGen-Int delivers every conversion to BedrockGen-Ex beside Geyser by itself, so there is nothing to copy.

## Connect Geyser

BedrockGen-Int links to BedrockGen-Ex with one line, so every later conversion reaches Geyser on its own.

<Steps>
### Find the secret on Paper

After the first start, `plugins/BedrockGen-Int/secrets.yml` contains a line like `secret: "bgx3:…"`.

### Paste it where Geyser runs

In `extensions/bedrockgen_ex/secrets.yml` on the Geyser host, paste the value as `id1: "bgx3:…"` and save. No restart is needed.

### Sync once

```text
/bedrockgenint sync
```

The command answers `installed on …` and every conversion from then on reaches Geyser by itself.
</Steps>

When Geyser runs as Geyser-Spigot on the same Paper server, there is nothing to connect. The output installs straight into Geyser. Several Paper servers can share one Geyser by adding one `id` line each in the same `secrets.yml`, and their packs merge.

<Details>
<summary id="direct-link"><strong>🔌 Prefer a direct link instead of cloud sync?</strong></summary>

Set `sync.mode: direct` in both `plugins/BedrockGen-Int/config.yml` and `extensions/bedrockgen_ex/config.yml`, then give Int the address and port where Ex listens.

```yaml
# Geyser: extensions/bedrockgen_ex/config.yml
direct:
  port: 8801

# Paper: plugins/BedrockGen-Int/config.yml
direct:
  address: "10.0.0.2"  # the Geyser host as Paper reaches it
  port: 8801           # the same port as in Ex
```

With Geyser on the same machine the address is `127.0.0.1`, and with several Geysers each one goes under `direct.targets` with its own name. `/bedrockgenint sync` then reports one line per Geyser, and `/bedrockgenint delivery use <ip[:port]>` sets the address from the console.
</Details>

<Callout type="info">
  On a proxy network, install Floodgate on the proxy and every backend server. Copy the proxy's `key.pem` to each backend Floodgate folder, then enable `send-floodgate-data: true` in the proxy Floodgate configuration.
</Callout>

## Conversion

<Callout type="important">
  Use Oraxen's `pack.generation.unprotected-location` export with BedrockGen's custom input command. This lets Oraxen keep protecting and obfuscating the pack it sends to players.
</Callout>

<Steps>
### Export a pack for BedrockGen

Open `plugins/Oraxen/settings.yml` and set `pack.generation.unprotected-location` to a ZIP path outside `plugins/Oraxen/pack`. Relative paths use the server working folder. Oraxen writes this readable export after pack generation and before obfuscation. It does not upload or send the export to players.

```yaml
pack:
  generation:
    unprotected-location: "./.output/oraxen-unprotected.zip"
```

### Match the mapping mode

BedrockGen can read either of Oraxen's appearance formats. `mapping_mode: auto` is recommended because it detects the format from the exported pack.

- `pack.generation.model-definitions: true` uses the `definitions` format and modern `item_model` files such as `assets/oraxen/items/<id>.json`.
- `pack.generation.model-data.float: true` uses the `legacy` format and numeric custom-model-data values.

### Regenerate the pack

```text
/oraxen reload pack
```

### Read your chest GUIs

```text
/bge gui import auto
```

Run this once before the first conversion. It reads the custom chest menus out of Oraxen and any other item plugins you have installed, so the conversion includes them. Skip it only if your pack has no custom menus.

### Convert the pack

```text
/bge convert --input=./.output/oraxen-unprotected.zip
```

Use the same path in `--input` that you set for `pack.generation.unprotected-location`. Running `/bge convert` without arguments opens a panel where you pick the source plugin and settings instead.

### Collect the output

When the conversion finishes, BedrockGen-Int has already sent the output to Geyser. Bedrock clients cache the pack, so a player who still sees the old pack rejoins once. If the console asked for a Geyser restart, restart it once.
</Steps>

<Details>
<summary><strong>🔓 Converting the protected pack instead</strong></summary>

BedrockGen can also read `plugins/Oraxen/pack/pack.zip` directly with `/bge convert oraxen`, but only when Oraxen's protection and obfuscation are disabled.

```yaml
pack:
  generation:
    obfuscation:
      type: NONE
    protection: false
```

This leaves the pack players download unprotected, so the unprotected export above is the recommended setup.
</Details>

<Callout type="info">
  Oraxen furniture rendering settings are configured under `mechanics.furniture.properties`. Set placed models separately under `mechanics.furniture.appearance`. Growth-stage files are assigned to the item that owns them during conversion.
</Callout>

## Commands

<Details>
<summary id="convert"><strong>🔄 Convert</strong></summary>

Opens the conversion panel to pick a source plugin and settings.

```yml
/bge convert
```

Converts the resource pack generated by Oraxen, reading `plugins/Oraxen/pack/pack.zip`.

```yml
/bge convert oraxen
```

Converts a pack ZIP from a custom path, such as Oraxen's unprotected export.

```yml
/bge convert --input=&lt;file&gt;
```

These commands require `BedrockGen.use`.
</Details>

<Details>
<summary id="status"><strong>📊 Status, cancel and report</strong></summary>

Shows the progress of a running conversion.

```yml
/bge status
```

Stops a running conversion.

```yml
/bge cancel
```

Prints the last conversion's report again.

```yml
/bge details
```

Lists items still waiting for a material, with the link to answer them.

```yml
/bge pending
```

</Details>

<Details>
<summary id="settings-commands"><strong>⚙️ Settings</strong></summary>

Shows every setting as clickable rows in chat.

```yml
/bge settings
```

Changes one setting from the console or in game.

```yml
/bge set &lt;setting&gt; &lt;value&gt;
```

Reloads BedrockGen's configuration. Requires `BedrockGen.admin`.

```yml
/bge reload
```

</Details>

<Details>
<summary id="gui-commands"><strong>🖼️ Chest GUIs</strong></summary>

Reads the custom chest menus from your installed item plugins.

```yml
/bge gui import auto
```

Starts live measurement while you open chest menus, for a menu that came out wrong.

```yml
/bge gui import live
```

Stops an active live measurement session.

```yml
/bge gui import live stop
```

Lists the chest GUI measurements saved by BedrockGen.

```yml
/bge gui list
```

Removes a saved chest GUI measurement.

```yml
/bge gui remove &lt;id&gt;
```

</Details>

<Details>
<summary id="misc-commands"><strong>🧩 Glyphs, scoreboards, skulls and learning</strong></summary>

Opens the emoji panel with what was converted and every switch.

```yml
/bge glyphs
```

Opens the scoreboard panel for the sidebar logo, background and score numbers.

```yml
/bge scoreboard
```

Registers the custom skull in your main hand for Bedrock. `/bge skull live` registers every custom head you hold, wear or see in menus until `/bge skull live stop`.

```yml
/bge skull
```

Remembers what custom items really are from what players hold, wear and see. Used for packs converted without their plugin.

```yml
/bge learn on|off|clear
```

</Details>

<Details>
<summary id="int-commands"><strong>🚚 Delivery (BedrockGen-Int)</strong></summary>

Sends the current output to Geyser right away and names every Geyser that installed it.

```yml
/bedrockgenint sync
```

Tells Int where Geyser is, once, when it did not find it on its own.

```yml
/bedrockgenint delivery use &lt;ip[:port]&gt;
```

Reloads `plugins/BedrockGen-Int/config.yml`.

```yml
/bedrockgenint reload
```

</Details>

## Chest GUIs

BedrockGen draws custom chest menus on Bedrock the way they look on Java. `/bge gui import auto` reads the menus from your installed plugins before the first conversion, so nothing has to be opened in game. When a single menu comes out wrong, open it in game and run `/bge gui import live` to measure it exactly as the server draws it. Live measurement stops automatically after five minutes.

Measured menus are managed from the `/bge` panel under GUI, where each menu can be switched off, re-scanned or given its own row count and offset. Measurements apply on the next `/bge convert`.

## Emojis and glyphs

Oraxen glyphs convert automatically and show on Bedrock at their authored size. The emoji panel under `/bge glyphs` controls the conversion, including the maximum glyph size and whether Bedrock's own letters stay intact under your emojis.

Use `plugins/BedrockGen/glyphs.yml` when you need to change a glyph's Bedrock size.

- `scale` multiplies the authored size while preserving the relative size between glyphs.
- `height` sets an exact pixel height and takes priority over `scale`.

<Details>
  <summary><strong>🔤 Glyph configuration</strong></summary>

```yaml
# plugins/BedrockGen/glyphs.yml
glyphs:
  farmer_tag:
    scale: 2.0
  god_tag:
    height: 36

fonts: {}
```

`glyphs` accepts glyph IDs, which are the keys in an Oraxen glyph file. It does not accept the glyph file name or texture path. `fonts` accepts font names and applies a setting to every glyph in that font.
</Details>

## Items without a material

Some models do not specify which vanilla material they represent. When BedrockGen meets one, the conversion pauses and chat offers a review link. Opening it starts a browser session where you fill in the material for each item, and the conversion continues by itself.

Answers are saved in `plugins/BedrockGen/materials.yml` and are not asked again for the same pack. Use either `paper` or `minecraft:paper`. Leaving a field empty converts the pack without a Bedrock mapping for that item. Set `skip_pending: true` to skip the prompt entirely; saved answers still apply.

## Settings

Everything can be set from the `/bge` panel in game or with `/bge set <setting> <value>`, and the values are saved as defaults for the next conversion. The main options are shown below in the same format as Oraxen's `settings.yml` documentation.

<Details>
<summary id="mapping-mode"><strong>🗺️ `mapping_mode`</strong></summary>

Selects how Geyser mapping rows are generated.

```yaml
pack:
  mapping_mode: auto
```

`mapping_mode` - Uses `auto` to detect the pack format, `legacy` for custom-model-data rows, or `definitions` for 1.21.4 item-model rows.<br />

</Details>

<Details>
<summary id="icon-size"><strong>🖼️ `icon_size`</strong></summary>

Controls the resolution of rendered inventory icons for 3D models.

```yaml
pack:
  icon_size: 128
```

`icon_size` - Sets the icon resolution. Valid values are `16`, `32`, `64`, and `128`. Other values use the nearest supported size.<br />

</Details>

<Details>
<summary id="transparency"><strong>🔳 `transparency`</strong></summary>

Controls how semi-transparent textures are handled during conversion.

```yaml
pack:
  transparency: true
```

`transparency` - Keeps semi-transparent and glowing textures that way instead of rendering them as solid blocks.<br />

</Details>

<Details>
<summary id="font"><strong>🔤 `font`</strong></summary>

Controls conversion of Java bitmap fonts into Bedrock glyph pages.

```yaml
fonts:
  enabled: true
```

`font` - Converts custom fonts so emojis can appear in Bedrock chat, names, and menus.<br />

</Details>

<Details>
<summary id="skip-pending"><strong>❓ `skip_pending`</strong></summary>

Controls what happens when an item has no vanilla material mapping.

```yaml
items:
  skip_pending: false
```

`skip_pending` - Skips the material review when enabled. Saved answers still apply, while items without an answer are left without a Bedrock mapping.<br />

</Details>

<Details>
<summary id="auto-deliver"><strong>🚚 `auto_deliver`</strong></summary>

Controls whether the output is sent to Geyser automatically.

```yaml
delivery:
  auto: true
```

`auto_deliver` - Sends `plugins/BedrockGen/output/` to Geyser through BedrockGen-Int after each conversion. When disabled, the output only stays in `output/`.<br />

</Details>

<Details>
<summary id="vanilla-assets"><strong>🧱 `vanilla_assets`</strong></summary>

Controls whether the pack's retextures of vanilla blocks and items are carried over.

```yaml
items:
  vanilla_assets: false
```

`vanilla_assets` - Carries the pack's own art for the game's own blocks and items. When disabled, only custom content travels to Bedrock.<br />

</Details>

## HUDs and interfaces

What Oraxen's pack retextures in the vanilla HUD, such as the hotbar, hearts and the experience bar, converts with the pack. HUD plugins that draw with fonts, including MythicHUD, BetterHud, CustomNameplates, LuxDialogues and Tooltips, need the <Highlight color="#1877F2" to="https://docs.bedrockgen.com/#en-hud">**BGHud add-on**</Highlight>, which lays out each frame on Bedrock the way Java draws it. BGHud replaces the older BedrockGenUi add-on.

## Supported features

- 🟢 × **Items, 2D and 3D.** 3D models become held Bedrock models and flat items become sprites.
- 🟢 × **Bows, crossbows, tridents and spears.** Draw, charge and throw poses are rebuilt for Bedrock.
- 🟢 × **Custom blocks.** Note-block, string, chorus, stairs, slabs, doors, trapdoors, and cross-shaped plants retain their supported shapes and sounds.
- 🟢 × **Block hitboxes.** Custom block collision sizes are converted.
- 🟢 × **Player armor.** Custom equipment textures render as worn armor, including armor trims.
- 🟢 × **Dyeable items and furniture.** Items, armor and furniture you can dye on Java keep their colour on Bedrock.
- 🟢 × **Glyphs and emotes.** Java bitmap fonts become Bedrock glyph sheets.
- 🟢 × **Custom sounds.** Sound events are remapped for Bedrock.
- 🟢 × **Item components.** Food, consumables, tools, repairable items, and use cooldowns are carried over.
- 🟢 × **Animated textures.** Animation strips are rebuilt as Bedrock frame animations.
- 🟢 × **Scoreboard pictures.** Logos, panels and backgrounds drawn by scoreboard plugins show on Bedrock.
- 🟢 × **Horse, wolf and llama armor.** Custom mob armor and llama carpets render on Bedrock.
- 🟢 × **Chest GUIs.** Custom backgrounds, title glyphs, row counts, and positioning are converted from measured GUIs.
- 🟠 × **Furniture.** Drawn by BedrockGen-Ex where Geyser runs. Position, scale, and offset use the model's display settings.
- 🟠 × **ModelEngine and BetterModel.** Converted and installed by BedrockGen-Int automatically when one of them is installed.
- 🟠 × **Custom elytras.** Wings convert with the pack and Bedrock players glide with them, drawn by BedrockGen-Ex.
- 🟠 × **Text displays and holograms.** Drawn as on Java by BedrockGen-Ex.
- 🟠 × **HUD plugins and dialogues.** BetterHud, MythicHUD, CustomNameplates and LuxDialogues need the BGHud add-on.

## Limitations

- 🔴 × **Custom paintings.** Bedrock players see the vanilla paintings.
- 🔴 × **Hopper, dropper, and dispenser reskins.** These screens are built into the Bedrock client and cannot be changed by a resource pack.
- 🔴 × **Item-frame furniture.** Furniture built on an item frame shows as a flat 2D icon. Furniture built on an item display converts in full.
- 🟠 × **Custom fishing rod line.** The rod converts and catches, but the Bedrock client draws no line for a custom rod.
- 🟠 × **GUI, HUD, and dialogue layout parity.** Java font shaders and Bedrock JSON UI render differently, so complex interfaces can require position or scale adjustments.

<Callout type="note">
  Most limitations come from Bedrock or Geyser rather than Oraxen or BedrockGen. Report one specific item, block, or furniture problem with a screenshot in the [BedrockGen Discord](https://discord.gg/4f3V6X2deY).
</Callout>
